react-hook-form and @hookform/resolvers were dropped for @tanstack/react-form. The shared layer is three files: context.ts (createFormHookContexts), fields.tsx (TextField, TextAreaField, SelectField, CheckboxField, ComboboxField, each reading its field from useFieldContext) and app-form.ts (createFormHook binding those, plus validatedBy and submitHandler).

The field components were chosen over the previous props-based shape (`<FormTextField control={form.control} name="x" />`). Keeping that shape would have required typing the form prop as ReactFormExtendedApi with `any` in every validator slot, which Biome's recommended noExplicitAny rejects; the createFormHook contexts give the same type safety on field names with no `any` in our source, at the cost of a render prop per field.

validatedBy(schema) reproduces react-hook-form's mode "onTouched": revalidateLogic({ mode: "blur", modeAfterSubmission: "change" }) with the schema as the onDynamic validator. A field is judged only once it has been left; from the first submit attempt every keystroke re-checks it, and submit validates and touches everything.

showViolations now calls form.setErrorMap({ onServer: { fields } }) with each violation wrapped as { message } so field errors carry one shape whether they came from zod or the API. The library clears the onServer entry on the next change or blur of that field, matching how setError behaved before. Errors read as field.state.meta.errors[0].message.

CustomerFields, shared by NewCustomer and CustomerDetail, is a withForm component taking `form` plus an optional lockNationalId.

TanStack Form has no field ref registration, so the focus-on-error affordance react-hook-form's field.ref provided is gone.
