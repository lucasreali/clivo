The five platform routes under /api/platform/tenants/{tenantId}/modules and .../parameters cannot be reached through the generated kubb clients. The API resolves the clinic in PlatformClinicScopeInterceptor by reading the URI template variable, so the Spring handlers never declare @PathVariable tenantId; springdoc therefore omits the variable from those operations and the generated Options types have path?: never. Passing the clinic is impossible, and the generated query keys carry no clinic either, so two clinics would share one cache entry.

src/features/platform/api/clinic-scope.ts addresses those five routes directly through the configured client in api/client.ts, and builds query keys shaped like the generated ones ([{ url, params: { tenantId } }]) so invalidation stays clinic-scoped. Every other platform endpoint (clinic list, get, provision, activate, deactivate, administrator creation) declares tenantId properly and uses the generated hooks as usual.

The proper fix is in ../clivo-api: annotate PlatformClinicModuleController and PlatformClinicParameterController with @Parameter(name = "tenantId", in = ParameterIn.PATH, ...) at class level, run ./gradlew test to refresh openapi.json, then pnpm generate-api. That was attempted and reverted here only because this machine has no Java toolchain (gradlew fails with JAVA_HOME not set). Once the document declares the variable, clinic-scope.ts can be deleted in favour of the generated hooks.
