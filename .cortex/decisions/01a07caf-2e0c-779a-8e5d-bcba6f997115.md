The regenerated openapi.json turned every identifier from int64 to a uuid-formatted string (customers, appointments, encounters, invoices, dependents, insurance plans, record templates, session userId/clinic). The committed screens still converted route params with Number() and typed their props as number, which vite build did not catch because it does not type-check; npx tsc --noEmit reported 33 errors.

All of them were migrated to strings: id props are string, route components pass the raw param through instead of Number(param), `x.id as number` casts became `as string`, and the select-driven ids in NewAppointmentDialog are passed as the strings they already were. useStartEncounter now reads the default record template with Parameters.text instead of Parameters.number, because recordTemplateId is a required uuid.

SignInRequest also lost its `clinic` field — the API resolves the tenant from the user — so the dead clinic input was removed from SignInForm rather than left as a control that goes nowhere.

Consequence: the verification loop is `pnpm check` plus `npx tsc --noEmit`, not `pnpm build`. The build compiles without type-checking, so a contract change can land green and still be broken.
