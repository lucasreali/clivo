The Clivo team's administration console is built inside this app rather than as a separate project. It sits under /console (pathless layout routes/console/_console.tsx, sign-in at /console/entrar) and is served by the new `platform` feature: clinic list, clinic onboarding, per-clinic module activation with dependency decisions, per-clinic parameters, and administrator creation.

Chosen because both surfaces share shared/ui, the generated client, the error handling and the session cookie; a second project would fork all of that to gain nothing. The surfaces stay separated by shell (ConsoleShell vs AppShell), by guard (/console/entrar vs /login) and by API prefix — /api/platform/** answers 404 to anyone without the PLATFORM_ADMIN role.

The console deliberately shows the whole module catalogue including what is switched off, the opposite of the clinic-facing ModuleGate rule, because the console's job is to show what is and is not contracted. Parameter editing reuses editorFor (variability mechanism C) through the existing ParameterControl, so a new parameter type is described by the API once and both surfaces render it.

The design mock (claude.ai/design, "CLIVO Console") was followed except where the API cannot back it: the rail uses the existing light system tokens instead of the mock's dark rail; TenantStatus only has ACTIVE/SUSPENDED/CLOSED so there is no "Implantação"; the clinic list endpoint carries no module data so the list shows segment instead of module chips; and there is no administrator listing endpoint, so that screen offers creation only and says why.
