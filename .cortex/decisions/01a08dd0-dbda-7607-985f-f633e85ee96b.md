CLIVO's user-visible copy was Brazilian Portuguese while code stayed English. The product is now English end to end.

What changed:
- Every user-visible string translated to English; `<html lang>` is now "en".
- Route segments renamed: /agenda→/schedule, /clientes→/customers (/novo→/new, /$id/historico→/$id/history), /atendimentos→/encounters, /financeiro→/billing, /configuracoes→/settings, /console/entrar→/console/sign-in, /console/clinicas/$tenantId/{modulos,parametros}→/console/clinics/$tenantId/{modules,parameters}, /console/nova-clinica→/console/new-clinic, /console/administradores→/console/administrators. routeTree.gen.ts regenerated with `pnpm generate-routes`.
- `shared/format/date.ts` and `money.ts` switched from the "pt-BR" Intl locale to "en-US".

Deliberate trade-off: the currency stays BRL. The API reports amounts in reais, so only the formatting locale changed (R$1,234.56 instead of R$ 1.234,56); switching to USD would misstate the values. For the same reason the Brazilian document masks and validators (CPF, CNPJ, CEP, phone) stay as they are — they are data formats, not copy — and their labels/messages are the English ones ("Invalid CPF. Check the 11 digits.", "Postal code").

The backend (../clivo-api) already speaks English: the OpenAPI spec, module names and the parameter `accepts` descriptions parsed by parameter-editor.ts contain no Portuguese, so nothing on the API side had to move.

CLAUDE.md and ARCHITECTURE.md were updated: the old "user-visible strings are Portuguese" convention is replaced by "everything is English".
