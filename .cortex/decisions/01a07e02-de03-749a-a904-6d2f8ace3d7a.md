A form-level standard schema in TanStack Form judges the whole draft on every validation run and writes the resulting message onto every field, not only the one that triggered the run. Leaving the CPF therefore wrote "Informe o telefone." onto the phone field, and with mode "blur" nothing re-judged that message when the typist later filled the phone, so a filled field kept a stale error under it.

The field components in src/shared/form/fields.tsx gate the display: `judged(field)` returns `field.state.meta.isBlurred || field.form.state.submissionAttempts > 0`. Before any submit, only a field the typist has actually left shows its message — and leaving it is exactly what re-runs the validation, so what shows is current. After the first submit attempt the mode is "change", every keystroke re-judges the whole draft, and every field may show its message; form.reset() zeroes submissionAttempts, so a reset form goes back to blur-only.

Gating on isTouched instead is not enough: typing into a field touches it without re-judging it, which is how the stale message reached the screen. Both failures were found by driving the real screens in a browser, not by the type checker.
